# Modelo Físico 

## 1. Introducción

Este documento describe el modelo físico  correspondiente a la Entrega 2 del proyecto **Sistema de Información para la Gestión Integral de la Copa Mundial de la FIFA**.

Aquí se fijan los tipos de datos concretos de Oracle, la nulabilidad de cada columna, las claves primarias, las claves foráneas con su política de eliminación, las restricciones `UNIQUE` y `CHECK`, y los índices de apoyo a las consultas más frecuentes. El script de creación está en el archivo `sql/entrega2/ddl/ddl_mundial.sql`.

### 2.2. Orden recomendado para cargar datos

Para poblar las tablas sin violar llaves foráneas, se insertan primero las tablas padre. Las autorrelaciones (`FASE_TORNEO`, `ENTE_FUTBOLISTICO` y `ENCUENTRO`) se resuelven insertando primero el registro padre o dejando la referencia en `NULL`.

`TORNEO_MUNDIAL` → `ENTE_FUTBOLISTICO` → `INTEGRANTE` → `PAIS_ANFITRION` → `FASE_TORNEO` → `CREDENCIAL_MEDIOS` → `BITACORA_CAMBIOS` → `LOCALIDAD` → `EQUIPO_NACIONAL` → `RECINTO_DEPORTIVO` → `PLANTEL_EQUIPO` → `ENCUENTRO` → `PARTICIPANTE_ENCUENTRO` → `TERNA_ARBITRAL` → `SUCESO_ENCUENTRO` → `RENDIMIENTO_JUGADOR` → `NOVEDAD_ENCUENTRO` → `BOLETO`

## 3. Detalle por tabla

### 3.1. `TORNEO_MUNDIAL`

> Representa cada edición de la Copa Mundial registrada en el sistema.

- **Clave primaria:** `TORNEO_MUNDIAL_PK` → `id_edicion`
- **Hija de:** —
- **Padre de:** `PAIS_ANFITRION` (vía `tiene`), `FASE_TORNEO` (vía `cuenta_con`), `CREDENCIAL_MEDIOS` (vía `acredita`)

**Columnas**

| # | Columna | Tipo Oracle | Nulo | Llave | Restricción |
| :-: | :--- | :--- | :-: | :-: | :--- |
| 1 | `id_edicion` | `INTEGER` | NOT NULL | PK | — |
| 2 | `anio` | `NUMBER` | NOT NULL | UK | UNIQUE `anio` |
| 3 | `nombre` | `VARCHAR2(100 CHAR)` | NOT NULL | — | — |
| 4 | `lema` | `VARCHAR2(200 CHAR)` | NULL | — | — |
| 5 | `fecha_inicio` | `DATE` | NOT NULL | — | CHECK `edicion_fechas` |
| 6 | `fecha_fin` | `DATE` | NOT NULL | — | CHECK `edicion_fechas` |

**Integridad**

| Constraint | Tipo | Definición | Al borrar |
| :--- | :-: | :--- | :-: |
| `TORNEO_MUNDIAL_PK` | PK | `id_edicion` | — |
| `anio` | UNIQUE | `(anio)` | — |
| `edicion_fechas` | CHECK | `fecha_fin > fecha_inicio` | — |

**Reglas implementadas**

- Solo puede existir una edición por año.
- La fecha de fin debe ser posterior a la fecha de inicio.
- No se puede eliminar una edición que tenga sedes, etapas o acreditaciones asociadas.

| 5 | `tipo_etapa` | `VARCHAR2(40)` | NOT NULL | — | CHECK `etapa_tipo` |

| Constraint | Tipo | Definición | Al borrar |

## 7. Política de integridad referencial

Cada clave foránea declara su comportamiento al borrar. Oracle no admite la cláusula `ON UPDATE`; como los identificadores son claves subrogadas que no se modifican, la intención `ON UPDATE RESTRICT` queda documentada como comentario en el DDL.

### 7.1. `ON DELETE RESTRICT`

Protege el historial: impide eliminar un registro padre mientras existan registros hijos.

Se aplica en: `tiene`, `posee`, `dispone`, `cuenta_con`, `representa`, `agrupa`, `crea`, `vincula`, `alberga`, `contiene`, `registra`, `es`, `relaciona`, `fk_estadistica_persona`, `acredita`, `recibe`.

Ejemplos:

- No se puede borrar un estadio que ya albergó o tiene programados partidos.
- No se puede borrar una persona con vínculos, asignaciones, acreditaciones, eventos o estadísticas.
- No se puede borrar una edición con sedes, etapas o acreditaciones.

### 7.2. `ON DELETE CASCADE`

Se usa cuando el registro hijo carece de sentido sin su padre: se eliminan automáticamente.

Se aplica en: `rellena`, `tienev2`, `genera`, `fk_estadistica_partido`, `fk_incidencia_partido`, `tienev1`, todas sobre `ENCUENTRO`.

Al eliminar un partido se eliminan sus participaciones, entradas, asignaciones arbitrales, eventos, estadísticas e incidencias.

### 7.3. `ON DELETE SET NULL`

Se usa en relaciones opcionales o jerárquicas, para que el hijo sobreviva sin su referencia.

Se aplica en: `se_conforma`, `se_forma_de`, `P2precede`, `precede`, `involucra`, `fk_auditoria_persona`.

Ejemplos:

- Si se elimina una etapa, sus subetapas quedan sin padre.
- Si se elimina una organización, sus suborganizaciones quedan independientes.
- Si se elimina un partido previo, el partido siguiente conserva su registro.
- Si se elimina la persona relacionada de un evento, el evento se conserva.
- Si se elimina la persona de un registro de auditoría, el registro se conserva.

## 9. Conclusión

El modelo físico implementa en Oracle las 18 tablas del modelo ampliado, con 18 claves primarias, 28 claves foráneas, 10 restricciones de unicidad, 22 restricciones de dominio y 5 índices de apoyo.

La política de integridad referencial combina tres criterios: `RESTRICT` para proteger el historial deportivo y administrativo, `CASCADE` para los datos que dependen por completo de un partido y `SET NULL` para las jerarquías y referencias opcionales.
